## Long-term Knowledge

### Architecture

<!-- lore:01a10279-c5d4-730d-a237-1c153b4c57de -->

- **Junior eval results reporting API**: Chose Junior’s Conversation reporting API over direct stored-row reads because eval assertions must match the user-visible view; tests read a \`Conversation\` and never inspect stored rows directly. \`readModelCalls()\` takes numeric usage from \`assistant_message\` events after the call’s sequence boundary; \`readModelTotals()\` aggregates by model. \`toHarnessRun()\` and \`combinedRun()\` expose those figures separately from auxiliary and gateway observations. Loaded history and calls outside agent history have no assistant-message call entry.

<!-- lore:01a1019b-f29e-75ad-a260-6023b18957d7 -->

- **Junior history replacement events**: Chose durable \`handoff\` and \`compaction\` history-replacement events over silently mutating Pi state because replay and crash recovery must know which active history and resume boundary were committed. Conversation events remain append-only; a replacement stores its history and updates Pi messages and the checkpoint together. A model-only switch is not a \`handoff\`: that event means history replacement, and old events must remain readable. Subsequent compaction must preserve the switched profile.

<!-- lore:01a103ed-576d-713a-b744-1549d229c213 -->

- **Junior Turn distillation lifecycle**: Chose an opt-in post-\`turn_completed\` Luna worker and a priced replacement before a later Turn’s first model request over reply-path distillation or in-turn rewriting because observation calls must not delay replies and active work needs exact history. \`JUNIOR_CONTEXT_DISTILLATION_ENABLED\` defaults off and gates both worker registration and use. The worker appends observations, not Pi messages; adoption commits one \`compaction\` replacement and a durable resume checkpoint. Existing capacity compaction remains the fallback.

<!-- lore:01a1019b-f4c0-7a60-9ac8-5eed1dc8c467 -->

- **Lore offline compaction assembly**: Chose offline assembly from stored distillations over a dedicated \`lore-compact\` LLM call because existing observations can form the summary without another synthesis call. \`generateCompactionSummary()\` urgently distills outstanding messages when needed, then assembles distillations and a bounded undistilled raw tail so a distillation failure does not erase recent work. The \`COMPACT_SUMMARY_TEMPLATE\` and \`buildCompactPrompt()\` in \`prompt.ts\` are legacy dead code, not the active compaction path.

### Decision

<!-- lore:01a1020a-e234-7db1-bdb1-643d5da8c937 -->

- **hexPlugin waitForHexThread**: Chose a runtime \`hexPlugin()\` with wrapped \`get_thread\` over the former manifest-only Hex plugin because model-driven polling incurred a serial model call for each wait. Expose \`create_thread\` and \`continue_thread\`, but let \`waitForHexThread\` make at most five bounded polls per invocation; the skill permits two invocations, ten polls total. Keep \`unknown\` and partial responses distinct from completion, and propagate authorization pauses rather than treating them as results.

<!-- lore:01a1020a-e0ff-7f5d-a537-a2ddb3dcff87 -->

- **shouldReuseHandoffHistory economics**: Chose priced reuse of safe, fully committed Junior history over automatically summarizing every in-turn model switch because a summary adds a model call and cold replacement write. \`shouldReuseHandoffHistory()\` compares summary, cold-write, and cached-read costs; reuse also requires target-model context fit, instruction provenance, and valid tool pairs. If prior work is not fully committed, use a summary—not a raw replacement. A close cost call keeps exact history; materially cheaper or unsafe reuse takes the summary path.

### Gotcha

<!-- lore:01a10ae1-00e1-7c11-b216-5bba9f0034da -->

- **compactWithDistillations replacement gates**: Trap: observations look sufficient to replace Junior history, but \`compactWithDistillations()\` also requires an exact projected-history match and rejects replacements at or above the model input limit. Fix: diagnose those gates separately from worker activation; below the capacity trigger, an unpriced replacement is rejected because a shorter history alone does not establish savings. A successful distillation replacement records its covered sequence, token estimates, expected calls, and pricing status.

<!-- lore:01a103ed-5938-7546-9495-d3ede9b29e51 -->

- **dashboard compaction reason union**: Trap: typing every \`compaction.details\` as \`reason: "capacity"\` looks right because capacity was the only prior replacement path, but distillation adds different detail fields. Fix: carry the capacity/distillation union through the Conversation API, dashboard context-event type, and Markdown export; read trigger, input limit, and message-count fields only for capacity compactions.

<!-- lore:01a103ed-58cc-7714-939b-2ac9818a8106 -->

- **distillation model-visible tokens**: Trap: summing historical assistant usage counters looks like a reasonable estimate of raw-history size, but those counters describe earlier requests, not text sent in the next request; they can make a shorter replacement appear no smaller. Fix: estimate serialized model-visible role and content for both raw and replacement history before applying the cost gate.

<!-- lore:01a102ee-9b93-7298-ac47-c8c0c8917b1c -->

- **gatewayModelCalls double-counting**: Chose getsentry/junior’s authorized Conversation reporting API over direct stored-row reads because evals must measure the user-visible view without leaking private payloads. \`readModelCalls()\` reads numeric assistant-message usage; \`readModelTotals()\` groups it by model. Keep auxiliary costs and gateway observations separate: they can overlap assistant calls. Conversation model-call reports allowlist provider, API, stop reason, and summarized usage; never expose opaque provider metadata.

<!-- lore:01a1030d-b03e-7d13-928d-d2e4a76c887f -->

- **gh run rerun --job databaseId**: Trap: the job number in a GitHub Actions browser URL looks like the identifier for \`gh run rerun --job\`, but the command requires the job’s \`databaseId\`. Fix: obtain it from \`gh run view \<run-id> --json jobs --jq '.jobs\[] | {name, databaseId}'\` and rerun the intended shard. \`gh run rerun --failed\` can also rerun failed dependencies, so it is not an exact-shard substitute.

<!-- lore:01a1019b-f456-73d9-a39b-886487528108 -->

- **gradient.ts currentTurnStart protection**: Trap: ordinary Lore windowing looks suitable for a long serial tool chain because it can strip old tool output, but \`currentTurnStart()\` protects the entire active turn and its tool pairs; \`tryFit()\` reserves that turn against the raw budget. A turn that alone exceeds the budget cannot fit normally. Fix: checkpoint completed in-turn work at a safe boundary while preserving the current instruction, open plan, provenance, recent results, and valid tool-call/result pairs. Tracked in BYK/loreai#1971.

<!-- lore:01a1020a-e4c4-779a-8382-284908f77107 -->

- **gradient.ts Layer-0 cost target**: Trap: Lore’s default \`$0.10\` cache-read target looks like a safe token cap because \`computeLayer0Cap()\` uses the routed model’s cache price, but at \`$0.20\` per million it yields 500k tokens, above Junior’s 400k host limit. The one-call compression comparison also omits summary work, uncached tail writes, and later calls. Fix: calibrate against capacity and measured multi-call costs instead of copying the fixed target into Junior. Tracked in BYK/loreai#1970.

<!-- lore:01a1019b-f530-7a0e-8414-b2ffd40b80de -->

- **gradient.ts per-request ModelBudget**: Trap: setting module-global model pricing and caps before an asynchronous transform looks convenient, but concurrent requests can then inherit another model’s limits. Fix: pass \`ModelBudget\` to \`transform()\` for synchronous application to that request; reset unavailable cache prices and Layer-0 caps rather than carrying prior values. Use the actual routed provider’s model specification.

<!-- lore:01a1029c-d121-7a46-8117-943dca263546 -->

- **Integration eval handoff cohorts**: Trap: aggregate Junior eval savings can look like a handoff win when reuse never activates, model routes differ, or a shard is missing. Fix: gate on actual activation; pair completed tasks by case and model sequence with complete cache counts; compare quality, latency, and cache-aware cost against repeated controls. One matched-route integration comparison found higher candidate cost overall and in handoff cases, so it established no savings. A cancelled shard makes available-case totals unsuitable as full-suite totals.

<!-- lore:01a1020a-e408-7ee4-aa41-a6f782c55e21 -->

- **Junior cache warming prefix churn**: Trap: copying Lore’s \`max_tokens:0\` cache warmer looks attractive when Junior has high cache-hit rates, but Junior’s unexplained near-full prefix rewrites and handoff replacements can make warmups paid cold writes rather than refreshes. Fix: measure prefix stability and provider zero-output support before a Junior pilot; warming does not remove Hex’s serial model calls. Lore’s warmer blocks churning or emergency-compacted prefixes and caps cycles even when forced.

<!-- lore:01a10303-2285-70ab-8913-6ae890b53607 -->

- **Junior continuity eval routing confound**: Trap: the large cost drop in Junior’s long \`continuity.eval.ts\` case looks like a handoff-history reuse gain, but the compared runs used different model routes and cache paths; the behavioral case made zero handoff tool calls. Fix: first establish that reuse activated, then compare matching model routes, per-call cache reads/writes, reply quality, and completed-task cost across repeated runs. A passing case or cheaper total cannot isolate the handoff change.

<!-- lore:01a1019b-f59b-78dc-b861-be7d235c3433 -->

- **Junior distillation retention boundary**: Trap: BYK/loreai distillations look reusable across getsentry/junior Conversations because both preserve history, but Junior’s actor authority and transcript-retention boundaries differ. Fix: bind each observation to its Conversation, covered event range, and active history version; remove it with the root-and-descendant purge tree. Reject writes to missing or purged Conversations and ignore stale-version worker results. Do not turn observations into cross-Conversation recall or Lore LTM.

<!-- lore:01a1019b-f37e-71e3-b659-56e3442af3c0 -->

- **Junior dual compaction targets**: Trap: describing Junior’s Pi agent-history compaction as reducing a 360k-token trigger to 288k looks right because visible Conversation-message compaction targets 80% of that trigger. Fix: distinguish the two paths. Both use the 90%-of-400k default capacity trigger, but Pi history is replaced with a summary plus retained instructions and has no fixed 288k target; visible Conversation-message compaction does.

<!-- lore:01a108c8-8d43-7ba0-b13d-4ab2d2ce1349 -->

- **Junior eval pluginTaskQueue wiring**: Trap: the eval fixture’s in-process \`conversationWorkQueue\` looks sufficient, but completed-Turn plugin tasks use a separate transport; an enabled run can make model calls yet record no observations. Fix: keep \`createApp()\`’s \`pluginTaskQueue(consume)\` contract, pass \`processPluginTask\` as \`consume\`, forward the returned sender through production conversation work, and use \`send: async message => track(consume(message))\` in the fixture so idle detection includes plugin tasks.

<!-- lore:01a1019b-f30c-7188-8ade-f89b17fbc314 -->

- **Junior retained instruction provenance**: Trap: a distilled summary can look like a substitute for prior user messages because it preserves their text, but it cannot inherit their authority or erase pending steering and valid tool pairs. Fix: treat compaction observations as unauthored, evidence-only context; preserve the current instruction and its author, recent raw work, open plan, and a resumable boundary. Explicit per-message provenance always wins. In-turn replacement also retains \`\<runtime-turn-context>\`; only \`\<current-instruction>\` authorizes action.

<!-- lore:01a1020a-e563-7368-ad68-0046487ab78b -->

- **Junior Vitest PostgreSQL setup**: Trap: running Junior’s targeted Vitest files without local services looks sufficient for a focused test, but global setup still connects to PostgreSQL at \`127.0.0.1:54322\` and fails with \`ECONNREFUSED\`. Start the Compose PostgreSQL/Redis services before database-backed tests; use \`tests/fixtures/sql\` and normally \`createJuniorSqlFixture\`. Nested fixture transactions use savepoints and never commit the outer test transaction, so tests remain isolated.

<!-- lore:01a103ed-59a8-72fb-9891-bf4cc6fb0360 -->

- **junior-tests-run-agent policy**: Trap: adding a realistic agent-running case under \`packages/junior/tests\` looks like strong integration coverage, but \`check-test-architecture.mjs\` limits those calls and requires agent behavior tests in evals with the agent fixture. Fix: use deterministic component coverage for worker and context logic, or an eval for actual agent behavior. Component tests must pass options to \`createApp()\` or \`agent()\` rather than mutate runtime config or reload modules; the architecture checker rejects that pattern too.

<!-- lore:01a102ee-9c08-7022-bb90-0c2e3ea11ddf -->

- **loadHistory skips agent execution**: Trap: a long \`history\` fixture looks like a long-running agent task because it contains earlier turns and completed tool calls, but \`loadHistory()\` stores those turns without running the agent. Fix: use a representative full-runtime, multi-turn scenario when measuring long-context cost, cache behavior, latency, or answer quality. Loaded history can establish context; it cannot supply measurements for the work it depicts.

<!-- lore:01a1019b-f3eb-7c0c-980f-6787d73d7d20 -->

- **Lore cached distillation prefix**: Trap: immediately injecting each new gen-0 distillation looks fresher, but rewriting a warm prefix destroys prompt-cache stability. Fix: \`distilledPrefixCached()\` holds even an empty prefix byte-identical while the session cache is warm; new rows join it after a cold boundary clears the cache. Lore uses a separate non-cached prefix for layers that already invalidate the cache.

<!-- lore:01a103ed-57eb-742d-8127-c7820fe52cee -->

- **pendingSegments full-text coverage**: Trap: marking a segment covered after rendering truncated text looks safe because the observer produced observations, but omitted source content would disappear from active history. Fix: never mark an entry covered unless the observer can read its full text. Images, unknown content parts, and entries above \`SEGMENT_TOKENS\` stay raw; \`pendingSegments()\` returns no segment if proposed coverage includes an unsupported entry, while preserving the raw tail and tool-call/result boundaries.

<!-- lore:01a10293-e5fc-7dbe-8c42-3e4b239f4fb8 -->

- **report.mjs rejects history.eval.ts fixture**: Trap: a failed Junior \`integration / report\` job looks like evidence that an evaluated agent failed, but \`packages/junior-evals/scripts/report.mjs\` can separately reject \`packages/junior-evals/src/fixture/history.eval.ts\` with “Expected an eval file inside junior-evals.” The same error occurred across baseline and candidate runs. Fix: inspect the selected attempt’s shard artifacts for case outcomes and costs, and diagnose report-job failures independently of shard or judge failures.

<!-- lore:01a10b6b-7f48-7787-9e60-b33e119692d5 -->

- **resource-scope.eval.ts coding suite**: Trap: placing a source-repair eval in the Conversation suite looks valid because the case runs, but that suite does not load \`coding-workspace-fixture\`; the agent can spend the run finding a workspace without repairing code or running the focused test. Fix: place it under \`evals/coding/\` and select it through the coding suite, which provides \`SKILL_DIRS\` and coding agent options.

<!-- lore:01a108e0-f57d-72cc-bf81-978b3b26324b -->

- **trigger-context-cost-evals on conflicted PR**: Trap: removing and reapplying \`trigger-context-cost-evals\` looks sufficient to start paired Evals, but a PR with \`mergeState: DIRTY\` may have no buildable merge revision; relabeling alone produced no Evals run. Fix: resolve the conflict, push the branch, and check that both \`context cost / off\` and \`context cost / on\` jobs started before scheduling artifact inspection. The run began after the merge-conflict resolution, though the conflict as the sole cause was not independently proven.

<!-- lore:01a10279-c692-7e9a-968f-407d5bfc9502 -->

- **waitForIdle 60-second timeout**: Trap: Junior’s \`waitForIdle()\` 60-second timeout looks like proof that distillation stalled, but it waits for both the in-process queue and background work and does not identify the blocker. It can end an eval before calls or usage counters are recorded, even though the behavioral/integration test timeout is 120 seconds. Fix: inspect events and pending work before attributing the timeout; treat absent usage as unknown and exclude that arm from activation, routing, quality, and cost comparisons.

<!-- lore:01a103ed-585c-7c72-b756-1ba145af6f4b -->

- **workerIsWorthRunning eligible prefix**: Trap: pricing only the next bounded batch looks conservative, but a long Turn may never qualify for distillation. Fix: \`workerIsWorthRunning()\` prices the full eligible prefix while processing remains bounded to twelve segments per Turn. \`distillCompletedTurn()\` also skips observation when there are no pending segments or no last-Turn model; zero observations alone cannot identify which gate blocked activation. The worker estimate retains 20,000 raw tokens, assumes 2,048 observation-output tokens per 16,000 removed, and prices the raw prefix as warm. \`shouldUseDistillations()\` requires at least 20% modeled savings after worker, cold-write, and expected cache-read costs; modeled savings do not prove completed-task savings.

### Pattern

<!-- lore:01a10303-21ea-732b-b9ee-a782f245a945 -->

- **Junior context evaluation ladder**: Steps: 1. Check the case’s routed-model economics, expected calls, and 60-second completion limit before triggering paired jobs — a passing but uneconomical case cannot test replacement. 2. Run off/on at the same SHA and model route; download only \`context-cost\` artifacts into separate temporary directories. 3. Compare completed cases using sanitized tool metadata: observations, priced replacements, quality, elapsed time, assistant plus auxiliary cost, and cache reads/writes. Repeat both settings. Gotchas: - Complete history and passing assertions look like activation, but zero observations or replacements prove no adopted distillation; diagnose the gate rather than lower the 20% threshold. - Missing usage is unknown, not zero; do not add overlapping \`gatewayModelCalls\` to reported cost. Verify: - \[ ] Both arms completed on matching routes with usable counters. - \[ ] Enabled arm stored observations and a \`priced: true\` replacement before attributing savings.

### Preference

<!-- lore:01a1020a-e31b-707e-8983-f04c78f2644e -->

- **Hex create_thread query contract**: For Junior Hex queries, always send one templated \`create_thread\` prompt with the entity’s primary key or identifier (never its name alone), exact caller field/table terms, an explicit period, all requested metrics, and structured output. Include supplied read-only SQL as specified; refuse writes. Use \`continue_thread\` at most once, only for a genuinely missing requested point: it reruns the Hex agent and adds minutes. Stop on authorization errors; retry transient network/server errors once. Never expose raw provider errors or fabricate partial results.
