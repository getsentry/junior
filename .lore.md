## Long-term Knowledge

### Architecture

<!-- lore:01a10279-c5d4-730d-a237-1c153b4c57de -->

- **Junior eval results reporting API**: Chose Junior’s Conversation reporting API over direct stored-row reads for eval assertions because tests must observe the dashboard’s view. \`readConversationDetail()\` requests \`/api/conversations/:id?limit=1000\` with \`x-fixture-viewer\`; \`readCallEvents()\` reads events after \`afterSeq\` and treats a \`handoff\` with \`triggeringToolCallId\` as completing that call. \`FixtureUsage.agentCostUsd\` and \`gatewayRequests\` become \`usage.metadata.costUsd\` and \`gatewayRequests\`; elapsed time becomes \`timings.totalMs\`. \`combinedRun()\` flattens call events and deduplicates conversation IDs.

<!-- lore:01a1019b-f29e-75ad-a260-6023b18957d7 -->

- **Junior history replacement events**: Chose durable \`handoff\` and \`compaction\` history-replacement events over silently mutating Pi state because replay and crash recovery must know which active history and resume boundary were committed. Conversation events remain append-only; a replacement stores its history and updates Pi messages and the checkpoint together. A model-only switch is not a \`handoff\`: that event means history replacement, and old events must remain readable. Subsequent compaction must preserve the switched profile.

<!-- lore:01a1019b-f4c0-7a60-9ac8-5eed1dc8c467 -->

- **Lore offline compaction assembly**: Chose offline assembly from stored distillations over a dedicated \`lore-compact\` LLM call because existing observations can form the summary without another synthesis call. \`generateCompactionSummary()\` urgently distills outstanding messages when needed, then assembles distillations and a bounded undistilled raw tail so a distillation failure does not erase recent work. The \`COMPACT_SUMMARY_TEMPLATE\` and \`buildCompactPrompt()\` in \`prompt.ts\` are legacy dead code, not the active compaction path.

### Decision

<!-- lore:01a1020a-e234-7db1-bdb1-643d5da8c937 -->

- **hexPlugin waitForHexThread**: Chose a runtime \`hexPlugin()\` with wrapped \`get_thread\` over the former manifest-only Hex plugin because model-driven polling incurred a serial model call for each wait. Expose \`create_thread\` and \`continue_thread\`, but let \`waitForHexThread\` make at most five bounded polls per invocation; the skill permits two invocations, ten polls total. Keep \`unknown\` and partial responses distinct from completion, and propagate authorization pauses rather than treating them as results.

<!-- lore:01a1020a-e0ff-7f5d-a537-a2ddb3dcff87 -->

- **shouldReuseHandoffHistory economics**: Chose priced reuse of safe, fully committed Junior history over automatically summarizing every in-turn model switch because a summary adds a model call and cold replacement write. \`shouldReuseHandoffHistory()\` compares summary, cold-write, and cached-read costs; reuse also requires target-model context fit, instruction provenance, and valid tool pairs. If prior work is not fully committed, use a summary—not a raw replacement. A close cost call keeps exact history; materially cheaper or unsafe reuse takes the summary path.

### Gotcha

<!-- lore:01a1019b-f456-73d9-a39b-886487528108 -->

- **gradient.ts currentTurnStart protection**: Trap: ordinary Lore windowing looks suitable for a long serial tool chain because it can strip old tool output, but \`currentTurnStart()\` protects the entire active turn and its tool pairs; \`tryFit()\` reserves that turn against the raw budget. A turn that alone exceeds the budget cannot fit normally. Fix: checkpoint completed in-turn work at a safe boundary while preserving the current instruction, open plan, provenance, recent results, and valid tool-call/result pairs. Tracked in BYK/loreai#1971.

<!-- lore:01a1020a-e4c4-779a-8382-284908f77107 -->

- **gradient.ts Layer-0 cost target**: Trap: Lore’s default \`$0.10\` cache-read target looks like a safe token cap because \`computeLayer0Cap()\` uses the routed model’s cache price, but at \`$0.20\` per million it yields 500k tokens, above Junior’s 400k host limit. The one-call compression comparison also omits summary work, uncached tail writes, and later calls. Fix: calibrate against capacity and measured multi-call costs instead of copying the fixed target into Junior. Tracked in BYK/loreai#1970.

<!-- lore:01a1019b-f530-7a0e-8414-b2ffd40b80de -->

- **gradient.ts per-request ModelBudget**: Trap: setting module-global model pricing and caps before an asynchronous transform looks convenient, but concurrent requests can then inherit another model’s limits. Fix: pass \`ModelBudget\` to \`transform()\` for synchronous application to that request; reset unavailable cache prices and Layer-0 caps rather than carrying prior values. Use the actual routed provider’s model specification.

<!-- lore:01a1029c-d121-7a46-8117-943dca263546 -->

- **Integration eval handoff cohorts**: Trap: lower aggregate cost across commonly passing Junior integration cases looks like evidence that \`shouldReuseHandoffHistory()\` saves money, but most cases may never hand off, cohort membership can vary, and reruns can reverse the cost result. Fix: read handoffs from each session’s \`events\`, compare always-handoff, never-handoff, and varying-handoff cohorts separately, and report completed-task cost, duration, requests, and quality. Confirm whether reuse or summarization ran and obtain per-call cache costs before attributing savings to either path.

<!-- lore:01a1020a-e408-7ee4-aa41-a6f782c55e21 -->

- **Junior cache warming prefix churn**: Trap: copying Lore’s \`max_tokens:0\` cache warmer looks attractive when Junior has high cache-hit rates, but Junior’s unexplained near-full prefix rewrites and handoff replacements can make warmups paid cold writes rather than refreshes. Fix: measure prefix stability and provider zero-output support before a Junior pilot; warming does not remove Hex’s serial model calls. Lore’s warmer blocks churning or emergency-compacted prefixes and caps cycles even when forced.

<!-- lore:01a1019b-f59b-78dc-b861-be7d235c3433 -->

- **Junior distillation retention boundary**: Trap: treating project-scoped Lore distillations as ready-made Junior memory looks plausible because both summarize history, but Junior’s Conversation privacy, actor authority, and transcript expiry differ. Fix: keep proposed Junior distillations scoped to their Conversation, tied to covered source event sequences, and purged with that Conversation tree; do not turn them into cross-Conversation recall or Lore LTM.

<!-- lore:01a1019b-f37e-71e3-b659-56e3442af3c0 -->

- **Junior dual compaction targets**: Trap: describing Junior’s Pi agent-history compaction as reducing a 360k-token trigger to 288k looks right because visible Conversation-message compaction targets 80% of that trigger. Fix: distinguish the two paths. Both use the 90%-of-400k default capacity trigger, but Pi history is replaced with a summary plus retained instructions and has no fixed 288k target; visible Conversation-message compaction does.

<!-- lore:01a1019b-f30c-7188-8ade-f89b17fbc314 -->

- **Junior retained instruction provenance**: Trap: replacing Junior Pi history with a summary looks sufficient because instruction text survives, but it can lose actor authority, pending steering, volatile runtime context, or valid tool-call/result boundaries. Fix: preserve the current instruction and its provenance verbatim, retain \`\<runtime-turn-context>\` for in-turn replacement, and commit a resumable boundary. Compacted conversation context is always unauthored, evidence-only context; only \`\<current-instruction>\` authorizes action. Explicit per-message provenance wins over inferred provenance.

<!-- lore:01a1020a-e563-7368-ad68-0046487ab78b -->

- **Junior Vitest PostgreSQL setup**: Trap: running Junior’s targeted Vitest files without local services looks sufficient for a focused test, but global setup still connects to PostgreSQL at \`127.0.0.1:54322\` and fails with \`ECONNREFUSED\`. Start the Compose PostgreSQL/Redis services before database-backed tests; use \`tests/fixtures/sql\` and normally \`createJuniorSqlFixture\`. Nested fixture transactions use savepoints and never commit the outer test transaction, so tests remain isolated.

<!-- lore:01a1019b-f3eb-7c0c-980f-6787d73d7d20 -->

- **Lore cached distillation prefix**: Trap: immediately injecting each new gen-0 distillation looks fresher, but rewriting a warm prefix destroys prompt-cache stability. Fix: \`distilledPrefixCached()\` holds even an empty prefix byte-identical while the session cache is warm; new rows join it after a cold boundary clears the cache. Lore uses a separate non-cached prefix for layers that already invalidate the cache.

<!-- lore:01a10293-e5fc-7dbe-8c42-3e4b239f4fb8 -->

- **report.mjs rejects history.eval.ts fixture**: Trap: a failed Junior \`integration / report\` job looks like evidence that an evaluated agent failed, but \`packages/junior-evals/scripts/report.mjs\` can separately reject \`packages/junior-evals/src/fixture/history.eval.ts\` with “Expected an eval file inside junior-evals.” The same error occurred across baseline and candidate runs. Fix: inspect the selected attempt’s shard artifacts for case outcomes and costs, and diagnose report-job failures independently of shard or judge failures.

<!-- lore:01a10279-c692-7e9a-968f-407d5bfc9502 -->

- **waitForIdle 60-second timeout**: Trap: \`The agent was not idle within 60 seconds\` looks like proof that a handoff or history-reuse path stalled, but \`waitForIdle()\` waits for both the in-process queue and background work; the timeout does not identify which remained active. Fix: inspect the relevant events and pending work before attributing an integration-eval timeout to a specific path.

### Preference

<!-- lore:01a1020a-e31b-707e-8983-f04c78f2644e -->

- **Hex create_thread query contract**: For Junior Hex queries, always send one templated \`create_thread\` prompt with the entity’s primary key or identifier (never its name alone), exact caller field/table terms, an explicit period, all requested metrics, and structured output. Include supplied read-only SQL as specified; refuse writes. Use \`continue_thread\` at most once, only for a genuinely missing requested point: it reruns the Hex agent and adds minutes. Stop on authorization errors; retry transient network/server errors once. Never expose raw provider errors or fabricate partial results.

This is a preference, not a launch requirement: a switch would permit controlled comparison and rollback without making it necessary to maintain two systems indefinitely.
