#3153 · Stop stacking sync PRs and looping base branches

1What broke

In sentry-docs, a weekly sync PR merges master into java-v9 while a long-lived collection PR goes the other way. When the sync merged, GitHub closed the collection PR as merged.

Nobody merged the collection PR.

2Why it happened

At the base commit, the walk steps from #701 to the PR below it, #700, and straight back. Nothing remembers where it has been, so only the depth limit stops it.

Recorded test run at base 4fc0a41. main stands in for master, feat/long-lived for java-v9.

3The fix, part 1

At the head commit, the same test stops before the walk starts: #701’s head is the trunk, so it returns no stack.

4The fix, part 2

Two feature branches can still point at each other. The walk now checks the chain first, meets #701 again at depth 1, and returns no stack.

5Proof it works

Same two tests, two commits. The base builds an 11-PR stack both times; the head builds none and sends no Stacks API write.

The old stacking test also fails now if the walk steps past the trunk.

6What’s left to decide

One case stays open: a feature PR into java-v9 still stacks on the collection PR. Merged as a group, it could land java-v9 on master early.
