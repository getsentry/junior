#3131 · Show skill text from every $skill-name reference

1The gap

In the Automation editor, View skill went to the plugin page or to /system#skills. Neither page shows what the skill tells Junior.

The ask, from the source Slack thread: the dashboard, and so the API, needs a way to load a skill and show its text.

2Now

Every $skill-name is now a link that opens the skill text in a drawer, over the page you were on.

ClaimA drawer beats a new skill page: the reader keeps their place in the editor.AgreeAsk

Text-only places (skill picker, draft changes, missing-skill error, loadSkill preview) show the same $name form.

3What the drawer shows

GET /api/skills/:name returns the list fields plus body: the SKILL.md text without its frontmatter. It leaves out the preamble Junior adds when it loads a skill for the model.

ClaimReaders should see what the author wrote, not the text the model receives.AgreeAsk

An unknown name returns 404 “Skill not found.” and the drawer says the skill is no longer installed.

4How we know it works

An API test checks one skill against its list entry, with no frontmatter in the body, and a 404 for an unknown name. The e2e test opens the drawer from View skill and switches to Raw.

// tests/integration/api/skills.test.ts
expect(skill).toMatchObject(listed!);
expect(skill.body).not.toMatch(/^---/);

// e2e/automation-editor.spec.ts
await page.getByRole("button", { name: "View skill", exact: true }).click();
await expect(skillDrawer).toContainText("Compare the release branch");
await skillDrawer.getByRole("button", { name: "Raw", exact: true }).click();
await expect(skillDrawer).toContainText("# Release check");
