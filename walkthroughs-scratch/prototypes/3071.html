#3071 · Share one filter for listed Conversations

1What changes

Five queries that list or search Conversations each repeat the same two conditions. Hiding Walkthrough generation runs would take five edits, and one missed edit leaks them into search.

Why now, from the source Conversation: Walkthroughs needed one place to hide their generation runs.

2The change

The PR moves both conditions into one function, listedConversation(), and all five queries call it. Each query keeps its own select, access filters and sort.

ClaimOne shared SQL condition is enough; a shared list query with options is not worth it.AgreeAsk
3What to check

The review is mechanical: each query loses the same two conditions and calls listedConversation() instead. Three queries differ in a small way, and none of the differences changes which rows match.

4How we know nothing changed

The fork test now reads the feed change token around a Quick question. The token stays the same while the question is unkept and changes on Keep, when the row appears in the list.

PR body: the test fails without the condition in the token query. Captured SQL matches before and after, apart from grouping and the Board reorder.

5What stays out

Retention in purge.ts, delivery pause, Location and participants mean “a root”, not “shown”, so they keep their own filter. Otherwise hidden Conversations would never be purged.
