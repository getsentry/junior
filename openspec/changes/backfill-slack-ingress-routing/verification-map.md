## Layer Rules

- Use `unit` for Slack payload normalization, edited-message extraction, message-kind classification, queue dispatcher routing, external-user filtering, and attachment fetcher rehydration.
- Use `integration` for Chat SDK handler registration, direct-message override behavior, assistant lifecycle routing, skipped-message propagation into runtime, and message-changed end-to-end behavior.
- Use `eval` only for model reply/no-reply judgment, and map those cases to `agent-turn-handling`, not this capability.
- Use `manual` for ownership/taxonomy decisions.

## Coverage Action Meanings

- `keep`: Current test/eval covers the scenario with the right scope and name.
- `rename`: Coverage is right, but taxonomy/name is misleading.
- `split`: File or case mixes multiple capabilities and should be separated.
- `move`: Coverage belongs in a different layer or package.
- `replace`: Existing coverage is low-fidelity or asserts the wrong contract.
- `delete`: Existing coverage duplicates another stronger check or asserts non-contract internals.
- `add`: No current coverage exists.
