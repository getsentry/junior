## Layer Rules

- Use `unit` for local deterministic reducers, parsers, signing, safe-boundary trimming, depth checks, and provider-retry boundary logic.
- Use `integration` for runtime resume wiring, Slack/thread state reconstruction, auth callbacks, locks, final delivery, and persisted completion/failure.
- Use `eval` for model-visible continuity and whether the resumed answer correctly uses prior context.
- Use `manual` only for taxonomy and architecture decisions that do not themselves prove runtime behavior.

## Coverage Action Meanings

- `keep`: Current test/eval covers the scenario with the right scope and name.
- `rename`: Coverage is right, but taxonomy/name is misleading.
- `split`: File or case mixes multiple capabilities and should be separated.
- `move`: Coverage belongs in a different layer or package.
- `replace`: Existing coverage is low-fidelity or asserts the wrong contract.
- `delete`: Existing coverage duplicates another stronger check or asserts non-contract internals.
- `add`: No current coverage exists.
