## Layer Rules

- Use `unit` for local deterministic logic such as Slack output splitting, status text formatting, footer rendering, and reply delivery plan helpers.
- Use `integration` for runtime Slack behavior, persistence, auth callbacks, queueing, assistant lifecycle, Slack API request shape, and file/image wiring.
- Use `eval` for model interpretation, prompt-following, reply quality, routing judgment, and tool-choice behavior.
- Use `manual` only for taxonomy inventory that does not itself prove runtime behavior.
- Use `unverified` only with a concrete follow-up task.

## Coverage Action Meanings

- `keep`: Current test/eval covers the scenario with the right scope and name.
- `rename`: Coverage is right, but taxonomy/name is misleading.
- `split`: File or case mixes multiple capabilities and should be separated.
- `move`: Coverage belongs in a different layer or package.
- `replace`: Existing coverage is low-fidelity or asserts the wrong contract.
- `delete`: Existing coverage duplicates another stronger check or asserts non-contract internals.
- `add`: No current coverage exists.
