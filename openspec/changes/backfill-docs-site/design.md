- content root: `packages/docs/src/content/docs`

## Page Contract

The current content schema makes `type`, `summary`, `prerequisites`, and `related` optional, while the documentation guidelines require them for new or substantially edited pages. This spec should reflect the project policy, not just the permissive schema.

Generated API pages are an exception: they are produced by TypeDoc and should not be forced into the authored page contract.

## Navigation Contract

Navigation is manual in `astro.config.mjs` rather than autogenerated. That is a product decision: the sidebar is a curated reader path, not a filesystem dump. When pages move, redirects preserve old public routes.

## Accuracy Contract

Docs are user-facing. They must describe supported setup and verification paths, not internal experiments. They must stay aligned with package manifests, plugin package lists, scaffolded CLI behavior, and runtime configuration where they document those surfaces.

## Undefined Behavior

- Frontmatter policy is stronger than the schema. The schema permits missing `summary`, `prerequisites`, and `related`, but the guidelines require them for new/substantial updates.
- Docs/package drift checks are manual. There is no automated check comparing plugin package lists across docs, README, release scripts, and manifests.
- Generated TypeDoc output is committed in `src/content/docs/reference/api`; the source-of-truth boundary between generated files and hand-authored API guide is implicit.
- Home page uses custom MDX/CSS and intentionally differs from normal docs page shape. The allowed scope for future homepage customization is not otherwise documented.
- Link integrity is mostly covered by Astro/Starlight build, but semantic link quality is human-reviewed.

## Verification Strategy

- `pnpm docs:check` runs `astro check` and `astro build`; it is the default docs validation command.
- `pnpm docs:build` is sufficient when the caller already ran type/content checks elsewhere or needs a production build.
- CI runs `pnpm docs:check`.
- Future drift checks should live under docs-site or release-packaging depending on whether they verify docs content or release package inventories.
